Subject: PowerDNS Security Advisory 2026-15 for DNSdist: Multiple issues

Hi all,

Today we released two new versions of DNSdist, 2.0.12 and 2.1.4, fixing 
several security issues that have been reported to us. These security 
issues are low to medium severity, and we recommend upgrading quickly.

The issues fixed in these releases are:

- CVE-2026-85561: When DNS over HTTPS is enabled and configured to trust 
incoming X-Forwarded-For headers, in addition to the use of the proxy 
protocol being enabled between DNSdist and one of its backends, an 
outgoing TCP connection could be wrongly reused for a query received 
over the same incoming DNS over HTTPS connection but with a different 
X-Forwarded-For header, causing the backend to consider the query as 
coming from the same remote client than the first query received on the 
outgoing connection.
- CVE-2026-85562: When DNS over HTTPS is enabled and configured to trust 
incoming X-Forwarded-For headers, and the reverse proxy placed in front 
of DNSdist does not replace existing X-Forwarded-For headers but merely 
append a new header to the query, the first header was used by DNSdist 
instead of the last one, making it possible for a client to spoof its 
own IP address.
- CVE-2026-85563: When DNS over HTTPS is enabled and a caching HTTP 
reverse proxy is used in front of DNSdist, it is possible to pollute the 
cache of the HTTP reverse proxy by sending DNS over HTTPS GET queries 
with a body. DNSdist should either refuse the query or ignore the HTTP 
body, but instead was processing the content of the HTTP body rather 
than the query present in the HTTP URL.
- CVE-2026-85564: When DNS over QUIC or DNS over HTTP/3 are enabled, an 
attacker can trigger a large memory usage by cancelling QUIC streams 
while DNSdist is still retrieving the corresponding responses from its 
backend. Instead of releasing the memory corresponding to the cancelled 
stream right away, DNSdist was mistakenly keeping it around until the 
end of the attacker-controlled QUIC connection.
- CVE-2026-85565: When DNS over HTTPS is enabled, an attacker can 
trigger a synchronization issue on outgoing TCP connections between 
DNSdist and its backend by sending oversized DNS over HTTPS queries. 
This could cause the backend to refuse queries, send a server failure, 
or just close the TCP connection.
- CVE-2026-85566: An attacker might be able to forge its own source IP, 
smuggle DNS records or bypass EDNS options filtering via a specially 
crafted DNS query when EDNS Client Subnet is enabled between DNSdist and 
its backend.
- CVE-2026-85567: Setting an empty API key was not properly disabling 
access to the internal HTTP API, despite being documented as such. This 
allowed an attacker whose IP address was allowed by the webserver ACL to 
bypass the authentication and get read-only access to the API.
- CVE-2026-123755: An attacker allowed to send AXFR or IXFR queries can 
cause an outgoing TCP connection to the backend to be stuck, causing a 
denial of service causing a denial of service to other clients when 
dnsdist tries to reuse the same outgoing connection.
- CVE-2026-123756: An attacker can cause a denial of service by sending 
crafted HTTP queries to the internal webserver. The webserver is not 
enabled by default and is protected by an ACL.


The full security advisory can be found at 
https://www.dnsdist.org/security-advisories/powerdns-advisory-for-dnsdist-2026-15.html 
and below.

Please feel free to contact me directly if you have any question.


PowerDNS Security Advisory 2026-15 for DNSdist: Multiple issues
===============================================================

CVE-2026-85561: Wrong remote DoH client IP passed to 
proxy-protocol-enabled backend
-----------------------------------------------------------------------------------

- CVE: CVE-2026-85561
- Date: 2026-11-12T12:00:00+01:00
- Discovery date: 2026-09-23T00:00:00+01:00
- Affects: PowerDNS DNSdist up to and including 2.1.3 and 2.0.11
- Not affected: PowerDNS DNSdist 2.1.4, 2.0.12
- Severity: Low
- Impact: Client IP spoofing
- Exploit: This problem can be triggered by a client sending crafted DoH 
queries when incoming X-Forwarded-For headers are trusted and the proxy 
protocol is enabled toward a backend
- Risk of system compromise: None
- Solution: Upgrade to patched version, do not rely on incoming DNS over 
HTTPS X-Forwarded-For headers, or do not enable the proxy protocol 
between dnsdist and its backends
- CWE: CWE-284
- CVSS: 3.1/AV:N/AC:H/PR:N/UI:N/S:C/C:L/I:L/A:N
- Last affected: 2.1.3,2.0.11
- First fixed: 2.1.4,2.0.12
- Internal ID: 557
- External ID: YWH-PGM6095-413
- External Reporter: Vitaly Simonovich

When DNS over HTTPS is enabled and configured to trust incoming 
X-Forwarded-For headers, in addition to the use of the proxy protocol 
being enabled between DNSdist and one of its backends, an outgoing TCP 
connection could be wrongly reused for a query received over the same 
incoming DNS over HTTPS connection but with a different X-Forwarded-For 
header, causing the backend to consider the query as coming from the 
same remote client than the first query received on the outgoing connection.

`CVSS Score: 5.4 
<https://nvd.nist.gov/vuln-metrics/cvss/v3-calculator?vector=3.1/AV:N/AC:H/PR:N/UI:N/S:C/C:L/I:L/A:N&version=3.1>`__

The remedy is: upgrade to a patched version, do not rely on incoming DNS 
over HTTPS X-Forwarded-For header, or do not enable the proxy protocol 
between dnsdist and its backends.

We would like to thank Vitaly Simonovich for bringing this issue to our 
attention.

CVE-2026-85563: HTTP body should not be processed on DNS over HTTPS GET 
queries
-------------------------------------------------------------------------------

- CVE: CVE-2026-85563
- Date: 2026-11-12T12:00:00+01:00
- Discovery date: 2026-09-21T00:00:00+01:00
- Affects: PowerDNS DNSdist up to and including 2.1.3 and 2.0.11
- Not affected: PowerDNS DNSdist 2.1.4, 2.0.12
- Severity: Low
- Impact: Cache pollution
- Exploit: This problem can be triggered by a client sending crafted DoH 
queries when a caching HTTP reverse proxy is present in front of DNSdist
- Risk of system compromise: None
- Solution: Upgrade to patched version, or do not place a caching HTTP 
reverse proxy in front of DNSdist
- CWE: CWE-436
- CVSS: 3.1/AV:N/AC:H/PR:L/UI:N/S:U/C:N/I:L/A:L
- Last affected: 2.1.3,2.0.11
- First fixed: 2.1.4,2.0.12
- Internal ID: 560
- External ID: YWH-PGM6095-310
- External Reporter: r0g3

When DNS over HTTPS is enabled and a caching HTTP reverse proxy is used 
in front of DNSdist, it is possible to pollute the cache of the HTTP 
reverse proxy by sending DNS over HTTPS GET queries with a body. DNSdist 
should either refuse the query or ignore the HTTP body, but instead was 
processing the content of the HTTP body rather than the query present in 
the HTTP path.

`CVSS Score: 4.2 
<https://nvd.nist.gov/vuln-metrics/cvss/v3-calculator?vector=3.1/AV:N/AC:H/PR:L/UI:N/S:U/C:N/I:L/A:L&version=3.1>`__

The remedy is: upgrade to a patched version, do not use a caching HTTP 
reverse proxy in front of DNSdist.

We would like to thank r0g3 for bringing this issue to our attention.
